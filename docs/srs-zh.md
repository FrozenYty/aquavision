## 1 引言

### 1.1 编写目的

本文档面向《基于改进 YOLOv8 的海洋牧场水下生物智能识别与监测系统》（以下简称"本系统"或"海瞳 AquaVision"）软件工程项目，详细描述系统的业务目标、用户角色、功能需求、数据需求、界面需求、算法与模型需求以及非功能需求，并给出验收标准与实施里程碑。本文档的读者包括：项目指导教师、开发小组成员、算法与测试人员以及项目验收评审专家。

本文档的具体用途包括：

- 作为需求分析阶段的正式交付物，明确系统"做什么"与算法"识别什么"，约定各模块边界与优先级，避免开发过程中的范围蔓延；
- 作为原型设计、数据库设计、概要设计与算法方案设计的直接输入，保证后续阶段的设计成果与需求逐条可对应；
- 作为算法训练、编码与测试阶段的验收依据，为功能测试用例、模型精度测试、性能测试与验收测试提供明确判定标准；
- 作为项目评审与结项答辩的正式材料，支撑需求可追溯性论证。

### 1.2 项目背景

海洋牧场与近海养殖网箱的资源调查、生物存量评估与敌害监控，长期依赖潜水员下水目视判读或人工回放水下录像。一次常规巡检往往产生数小时的 1080P 水下视频，人工判读需要数倍于拍摄时长的时间，且判读结果受人员经验、疲劳程度与主观判断影响显著，据本组对 3 段影像的人工判读试算，同一物种的计数差异可达 20%；历史影像资料大多以文件形式散落存储，既无法检索，也无法形成可比较的时间序列，资源变化趋势、敌害暴发预警与投放效果评估缺少客观数据支撑。

水下影像的成像条件又给自动识别带来特殊困难：水体对红光的强吸收造成整体色偏偏蓝偏绿，悬浮颗粒与浮游生物造成散射与雾状模糊，光照不均与人工光源形成亮斑与暗区，底栖生物（海参、海胆、扇贝、海星）常与礁石、海草背景高度相似且相互遮挡，鱼群目标小、密集、运动模糊明显。直接用通用数据集上训练的检测模型迁移到水下场景，往往出现漏检、误检与同帧重复计数，难以满足业务精度要求。

本项目面向海洋牧场巡检、近海网箱养殖监测与渔业资源调查三类业务，构建一套以 YOLOv8 目标检测算法为核心、覆盖"影像采集与接入—智能识别与计数—人工复核—统计分析—数据标注与模型迭代"完整闭环的 Web 系统。系统把水下影像转化为结构化的物种、数量、位置与时间数据，支撑资源密度评估、变化趋势分析与敌害预警，并为后续接入水下机器人（ROV）实时视频流、边缘端轻量化部署预留扩展接口。

### 1.3 项目范围

#### 1.3.1 建设目标

- 建立统一的水下影像资源管理体系：覆盖采集会话、监测点位、拍摄参数与水体条件，支持多维检索。
- 实现以 YOLOv8 为核心的水下生物自动识别与计数：对采集帧输出物种类别、位置框、置信度与去重后的个体数量。
- 打通"自动检测—人工复核—结果入库"的质量闭环：自动结果可被人工复核修正，修正结果回流为训练样本，形成模型迭代通道。
- 支撑多维统计分析与预警：按点位、时间、物种输出组成结构、密度分布与变化趋势，并按规则触发异常提醒与趋势预警。
- 在 8 周内交付一个可运行、可演示、算法与业务闭环完整的 Web 系统，并通过规范的过程文档证明团队具备软件工程实践能力。
- 打开系统即可从摄像头连续采集，无需任何文件导入。
- 改进模型较基线 mAP@0.5 提升 ≥0.03，FPS 不低于基线 90%。

#### 1.3.2 业务范围（包含）

- 用户注册登录、角色权限、团队与账号管理、操作日志与审计。
- 本机摄像头连续采集、元数据登记、质量判定与重拍、存储与清理策略。
- 图像识别与批量识别任务的创建、队列调度、进度监控、取消重试与任务重跑。
- 模型版本注册、上下线与切换、推理引擎与设备配置、模型评估指标记录与基线对比、分类别置信度阈值管理。
- 检测结果浏览、人工复核与修正、筛选与批量操作、多格式导出（CSV / JSON / COCO / VOC / 标注图与标注视频）。
- 物种字典与图鉴、难例样本库、数据在线标注、数据集版本管理、训练任务管理与指标可视化。
- 监测点位与采集会话管理、质量异常提醒、统计看板与报表导出。
- 系统参数配置、运行监控、公告消息、数据字典与编码规则、备份恢复。

#### 1.3.3 业务范围（不包含）

- 不控制水下机器人与摄像机的姿态、航迹与云台，不做水下导航与防水外壳工程化；采集在本机完成。
- 不接入真实海洋牧场的业务生产系统与缴费结算系统，全部使用教学演示数据与模拟业务流程。
- 不提供渔业捕捞决策、增殖放流方案与病害诊断处方，分析结果与告警仅作数据参考与技术提示。
- 不实现生物个体的跨天重识别（ReID）与生长曲线精确拟合，体长估算以像素标定为基础，精度标注为估算值。
- 不包含移动 App 原生端与小程序，仅提供响应式 Web 页面；不做多租户 SaaS 化与跨组织数据隔离。

## 2 项目概述

### 2.1 产品定位与总体目标

海瞳 AquaVision 是一套面向海洋牧场、近海养殖网箱与渔业资源调查场景的水下生物智能识别与监测 Web 系统。系统以"影像接入—智能识别—人工复核—统计分析—模型迭代"为主链路，把原本割裂的水下拍摄、人工判读、纸质记录与模型实验这四类动作统一到一套数据模型上：对业务人员而言，它把每一段水下影像转化为可检索、可比较、可导出的物种与数量数据；对算法人员而言，它把每一次误检与漏检沉淀为可回流训练的标注样本，使模型精度随使用持续提升。系统的定位不是替代渔业技术人员的专业判断，而是把人从重复性的目视判读中解放出来，让专业人员只处理机器不确定的部分，并让每一次人工判断都成为模型改进的输入。

系统总体目标如下：

- 单帧端到端识别响应不超过 1.5 秒，连续采集不低于 1 帧／秒，单帧结果可追溯到所用模型版本。
- 在测试集上核心生物类别检测的 mAP@0.5 不低于 0.75，个体计数相对人工判读的偏差不超过 15%。
- 人工复核结果可一键回流为训练样本，模型迭代一次的完整流程（标注—训练—评估—上线）控制在 1 个工作日内。
- 任意一次检测结果可追溯到具体的影像文件、模型版本、检测参数与操作人，保证分析结论可复现、可审计。

### 2.3 典型业务场景

场景 1：采集与即时识别。巡检员把四类靶标放入观测水箱，摄像头固定在水箱外壁并锁定曝光。点击“开始采集”，系统以 1 帧／秒连续抓取，主屏实时叠加检测框，3 秒内在右侧显示“海参 3、海胆 2、扇贝 4、海星 1”，并给出本帧端到端耗时。

场景 2：质量拦截与重拍。抽出一张磨砂膜使水体变浑，画面整体发灰。系统对该帧打出质量分 48 分，标记“需重拍”，拦在识别队列之外；移走磨砂膜后重新采集，质量分 86 分，自动进入识别，计数随之更新。

场景 3：复核与样本回流。分析员在复核工作台发现一只海参被误判为礁石，补画一个框并改类别。提交后计数由 10 变为 11，该帧自动进入难例池，数据集版本由 DS-V2 升为 DS-V3，页面上三处变化同时可见。

场景 4：实验与上线。算法员用 DS-V3 训练改进模型，实验记录页显示新模型较基线 mAP@0.5 由 0.76 升至 0.83、FPS 由 42 降至 39。确认指标达标后注册为候选版本并上线，此后新建的识别任务自动使用新模型，任务详情记录版本号。

场景 5：统计与报告。分析员按“本月”生成巡检报告，内容包括物种组成、点位分布、质量拦截率与告警摘要，页脚标注所用模型版本与统计口径。报告以 Markdown 交付，历史版本保留可回溯。

### 2.4 系统总体架构与数据流

系统由采集层、服务层与展示层构成，三层之间只通过进程内调用与本地文件交换数据，不依赖任何外部设备或网络推流。这一设计的直接目的是满足“影像必须由摄像头获取”的约束：系统不提供从本地磁盘选择图片进入识别的入口，识别队列中的数据只可能来自本机摄像头的实时抓取。

#### 2.4.1 三层职责

- 采集层：USB 摄像头、触发板与浊度传感器。负责抓取原始帧、锁定曝光与白平衡、上报水体参数，不做任何推理。
- 服务层：采集服务、识别服务、任务队列、文件存储与 PostgreSQL。负责质量判定与入库、调度识别、结果落库与统计聚合。
- 展示层：浏览器页面 13 个。负责采集控制、结果复核、统计报告与模型实验。

#### 2.4.2 一帧数据的七个环节

- ① 打开摄像头：启动时枚举本机视频设备，默认取第一个可用设备。
- ② 锁定曝光：读取当前曝光值并锁定，同时固定白平衡与增益；锁定失败则拒绝开始采集。
- ③ 抓帧与读传感：按设定帧率（默认 1 帧／秒）取帧并丢弃首帧，同时读取浊度，随帧一并上报。
- ④ 质量评分：计算清晰度、亮度、色偏三项加权分，低于 60 分判为需重拍。
- ⑤ 入库登记：按“点位／日期／序号”落盘，写入影像表并生成资源编号。
- ⑥ 进入识别：合格帧进入识别队列；不合格帧只入库、不排队，并提示重拍。
- ⑦ 结果呈现：识别结果写入目标表，页面按任务聚合展示，端到端耗时同时记录。

#### 2.4.3 采集接口约定

- 设备：本机 UVC 摄像头，1080P，MJPEG 或 YUYV，设备索引可配置。
- 曝光：手动曝光，快门与增益固定；锁定后帧间平均亮度差不超过 10%。
- 帧率：默认 1 帧／秒，可调范围 0.2～5 帧／秒。
- 时间戳：以服务端接收时刻为准，精确到毫秒，入库同时保存 UTC 时间。
- 幂等：同一采集会话内帧序号唯一，重复抓取不产生新记录。
- 环境参数：浊度以相对值随帧上报（0 为清澈，100 为最浑），采样周期 5 秒；传感器缺失时该字段为空，不参与统计。
- 失败处置：摄像头不可用时，本次采集标记失败并提示检查设备，不产生空记录。

## 3 功能需求

### 3.1 系统功能结构

系统按业务链接划分为 8 个一级模块。与常见的“按技术分层”划分不同，这里的模块边界按“一次采集到一份报告”的业务流转确定，每个模块都能对应到一个明确的界面与一组数据表。

M1 用户与权限管理

模块定位：提供登录、角色权限、账号维护与操作审计，是全系统的入口与安全基础。

- FR-M1-01 登录与会话 —— 手机号或邮箱登录、图形验证码、失败锁定、令牌签发与刷新。
- FR-M1-02 角色与权限控制 —— 采集员、分析员、算法员、管理员四类角色的权限边界，服务端强制校验。
- FR-M1-03 账号管理与重置 —— 管理员的建号、停用、恢复与密码重置。
- FR-M1-04 操作日志与审计 —— 记录登录、复核、上下线、参数变更等关键动作供追溯。

M2 采集与质量控制

模块定位：从本机摄像头抓取帧，完成质量判定、入库与清理，是识别任务的数据入口。

- FR-M2-01 单帧采集与入库 —— 接收帧并登记设备、点位、时间戳与曝光参数，生成资源编号。
- FR-M2-02 定时巡拍与连续采集 —— 按计划周期触发采集，自动形成批次。
- FR-M2-03 图像质量判定与重拍 —— 按清晰度、亮度、色偏打分，低分帧拦截并提示重拍。
- FR-M2-04 采集批次与影像检索 —— 按点位、时间、采集会话组合检索批次与帧。
- FR-M2-05 存储策略与清理 —— 按保留天数清理中间文件，生成可查的清理清单。

M3 实体识别

模块定位：以 YOLOv8 改进模型对采集帧执行目标检测，输出类别、位置、置信度与计数。

- FR-M3-01 即时识别 —— 单帧触发识别，端到端返回结果与叠加图。
- FR-M3-02 批量识别与队列 —— 按批次或帧列表排队识别，支持进度、取消与失败重试。
- FR-M3-03 识别参数配置 —— 置信度、IoU、单图上限与类别筛选，参数随任务固化。
- FR-M3-04 结果浏览与计数 —— 结果图与目标列表联动，给出分类计数。
- FR-M3-05 结果导出 —— 导出 CSV、JSON 与标注图，坐标统一为相对值。

M4 复核与回流

模块定位：对自动结果做人工修正并留痕，把修正结果沉淀为训练样本，形成模型迭代通道。

- FR-M4-01 复核工作台 —— 在结果图上增、删、改框与类别，提交复核结论。
- FR-M4-02 复核留痕与版本 —— 每次复核生成新版本，支持差异对比与回滚。
- FR-M4-03 难例样本集 —— 自动收集低置信、被修正与跨模型不一致的样本。
- FR-M4-04 数据集导出 —— 按样本范围与划分比例导出 YOLO 格式数据集并记录快照。

M5 统计与报告

模块定位：把识别结果转化为物种组成、时空分布与变化趋势，并输出可交付的巡检报告。

- FR-M5-01 物种组成统计 —— 按类别统计数量、占比与平均置信度，支持口径切换。
- FR-M5-02 点位与时间分布 —— 点位密度热力图与排行，支持下钻。
- FR-M5-03 趋势与同比环比 —— 按日、周、月粒度给出变化率与显著波动标记。
- FR-M5-04 巡检报告生成 —— 按模板汇总形成可下载的报告文件。

M6 模型与实验

模块定位：登记模型版本与训练实验，管理上线与回滚，维护物种字典与分类别阈值。

- FR-M6-01 模型版本登记 —— 登记版本名、权重、数据集与评估指标。
- FR-M6-02 上线与回滚 —— 单线模型切换，保留变更记录。
- FR-M6-03 实验记录与指标对比 —— 基线与改进实验同表对比，支持消融查看。
- FR-M6-04 物种字典与分类别阈值 —— 维护类别码、大类与默认置信度阈值。

M7 系统配置

模块定位：提供参数配置，保障系统长期可运行、可维护。

- FR-M7-01 系统参数配置 —— 保留天数、并发上限、默认阈值等参数外置可改。

M8 运维监控

模块定位：提供运行监控与站内消息，保障系统长期可运行、可维护。

- FR-M8-01 运行监控 —— 队列长度、GPU 显存、磁盘占用与任务失败率。
- FR-M8-02 站内消息与异常提醒 —— 采集失败、任务失败、报告完成等事件按角色推送。

### 3.5 算法需求（改进方案与指标）

本节回答标题里的“改进”到底改了什么。原则是：只做能在一周内跑完、能在一张表里说清、能在答辩时指着图讲的改进。因此不追求新结构，只做三处有独立贡献、且能做消融的点。

#### 3.5.1 基线与训练条件

基线为 Ultralytics YOLOv8n，输入 640×640，训练 100 轮，批量 16，初始学习率 0.01，随机种子固定为 42，数据取自 DUO 公开数据集的四个类别（海参、海胆、扇贝、海星）。类别选择依据：海参、海胆、扇贝为海洋牧场主要经济种，海星为扇贝养殖的主要敌害；四类均为 DUO 已有标注对象，可直接复用现成标注。基线的一切配置都写入训练实验表，后续每个改进实验只改一处，其余保持一致，保证对比是干净的。

#### 3.5.2 三项改进点

**表 3-41 三项改进点定义**

| 编号 | 改进点 | 所属层次 | 具体做法 | 预期贡献 |
|---|---|---|---|---|
| AR-01 | 水下色彩校正预处理 | 数据层 | 灰度世界白平衡＋红通道补偿＋CLAHE 对比度受限直方图均衡；训练与推理使用同一套算子，可开关 | 缓解偏蓝偏绿与雾状模糊，提升小目标与低对比目标的召回 |
| AR-02 | 注意力增强 | 结构层 | 在 Neck 输出送入检测头之前插入 EMA 注意力模块，不改动主干 | 增强目标区域响应，抑制礁石与海草背景的误检 |
| AR-03 | 边界框损失改进 | 优化层 | 将 CIoU 替换为 WIoU v3，降低低质量样本对回归的干扰 | 提升定位稳定性，对遮挡与模糊样本更鲁棒 |

#### 3.5.3 实验设计与消融

五个实验按“逐项加码”排列，E0 为对照，E4 在改进方案上叠加自采数据微调。同一实验的随机种子固定，重复运行两次的指标差异须小于 1%，否则视为不可复现。

## 5 界面与交互需求

### 5.1 界面风格与布局规范

系统界面整体采用深海蓝（主色 #0B4F6C）与青绿（辅助色 #01BAEF）的海洋基调，配白底浅灰卡片背景；检测结果类别按物种使用固定的区分色（海参橙、海胆紫、扇贝粉、海星黄）；“未识别”“待复核”“低置信”三种状态以虚线框、角标与半透明填充区分，不得仅以颜色区分。。整体布局采用"顶部导航 + 左侧菜单 + 内容区"三段式结构：顶部导航放置系统标识、当前用户与消息入口；左侧菜单按业务域分组折叠；内容区统一使用卡片容器、统一的表格样式与分页控件。标注与复核工作台采用画布居中、工具栏悬浮的沉浸式布局，画布支持滚轮缩放与拖拽平移。统计类页面以 ECharts 图表为主，图表配色与类别色保持一致。

交互规范：所有列表页支持关键词检索 + 条件筛选 + 分页三件套；所有耗时操作（采集、识别、导出、训练）必须有进度反馈且可后台执行；所有破坏性操作（删除、取消、回滚、恢复）必须二次确认；表单校验错误就近提示并高亮字段；空数据状态给出引导性文案与操作入口。

### 5.3 关键交互流程

流程 1（采集识别主链路）：采集控制页点击开始 → 抓帧与质量评分 → 合格入库并生成编号 → 自动或手动发起识别 → 结果页显示叠加图与计数 → 低置信结果进入复核队列 → 复核确认后统计与报表更新。

流程 2（复核回流链路）：复核工作台打开待复核队列 → 增删改框与类别 → 提交生成新版本并更新计数 → 被修改帧自动进难例池 → 按样本范围导出数据集 → 记录数据集版本号，供训练使用。

流程 4（异常处置链路）：质量分低于阈值、摄像头不可用或识别任务失败时，系统生成站内消息 → 采集员或管理员查看处置建议 → 调整参数或重拍 → 处置结论回填，形成闭环。

流程 5（同框对比，演示用）：同一帧图像分别送入基线与改进模型 → 左右分栏渲染 → 差异框描边高亮 → 同屏显示两模型 mAP、FPS 与单帧耗时。

流程 6（质量拦截，演示用）：抽出磨砂膜使画面变浑 → 系统评分低于 60 分 → 标记需重拍并拦在识别队列外 → 移走磨砂膜重拍 → 评分回升，自动进入识别。

流程 3（训练上线链路）：算法员登记实验并选择数据集版本 → 训练完成后填写指标 → 系统与基线对比生成对比表 → 指标达标则注册候选版本 → 上线并记录变更 → 后续任务自动使用新版本。

### 8.2 交付验收物

结项验收时应提交：①系统可运行环境与种子数据；②本文档及其评审记录；③原型、数据库设计、概要设计与接口文档；④基线与改进模型权重及评估报告；⑤测试计划、用例、缺陷报告与测试总结；⑥部署手册与用户手册；⑦结项验收报告与答辩材料。全部文档以 Git 仓库归档，关键节点提交指导教师留存。

### 8.3 缺陷与遗留问题处理

验收测试发现的缺陷按严重程度分级处置：致命（系统不可用、数据丢失、精度指标不达标）与严重（核心链路阻断、权限失效）缺陷必须在验收前清零；一般缺陷（非核心页面、提示与体验类）遗留不超过 5 个，逐条登记遗留问题清单、影响说明与处置计划，经指导教师确认后随结项材料归档。模型精度未达标时须提交改进实验记录与后续计划，不得以调低阈值的方式通过验收。

## 附录C 术语一致性说明（编制说明）

本文档与后续原型说明、数据库设计、概要设计共用同一套术语体系：物种类别以物种字典（species_dict）为准；功能编号 FR-M<模块号>-<序号> 与表 3-1 一一对应；用例编号 UC-XX 与 3.4 节一一对应；验收编号 AC-XX 与第 8 章一一对应；数据表命名采用小写下划线风格，字段字典以 4.2 节为准。文档中"识别""检测"均指基于 YOLO 的目标检测；"计数"均指经跨帧去重后的个体数量统计；"线上模型"指当前默认用于新任务的模型版本。各文档如有出入，以 V1.1 送审稿为准。表号按章连续编排，格式为“表 <章号>-<序号>”，附录表格为“表 <附录字母>-<序号>”，不使用“表 3-x”类占位编号。
