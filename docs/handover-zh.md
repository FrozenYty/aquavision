## 二、给高天翔：后端与模型

### 2.0 顺序，以及第一件要说的事

这一节的三条任务**不是并行的**。依赖关系是：

```
P2-06a  划分落盘
   └─ P2-06b  跑出基线
        └─ P2-06c  权重登记上线
             └─ P2-05b  检测链路        ← 只有这一段在等
P2-07   契约测试                        ← 从这里开始，没有任何前置
P2-05a  队列消费者，用合成数据          ← 同样没有前置
P2-15   契约 §7 的三个问题               ← 没有前置，而且它解开前端那条
```

**在所有事情之前：先说数据集在哪。** `scripts/prepare_dataset.py` 读 `data/raw/DUO/DUO`，而这个目录
在当前工作区里**不存在**。如果数据只在一台机器上，那它就是一个阻塞项，**该在上午第一小时说出来**，
而不是周四发一条消息解释为什么没有合并。

**这周四条规则，不是风格偏好：**

1. **没有 PR 就是没开始。** 没有分支等于没开工，如实报「未开始」，不要报「进行中」。
2. **下班前还开着的 PR，要有一句话说明为什么。** 沉默看起来像进展，但它是沉默。
3. **PR 更小、更频繁。** `P2-06` 是三次合并，不是一次。挂了三天还没合的分支没法评审，冲突还会变成
   别人的问题。
4. **检查输出贴进 PR。** 全部，每次。要贴哪些见第四节。

### 2.1 收尾 `P1-02`（任务 `P2-05`）

**开分支之前先看完这一节。** `P1-02` 的主体已经由组长做完了，因为阶段门禁等不到周一。
重做一遍会浪费一天，还会丢掉现有测试。

已经有了、不要重写的：

| 部分 | 位置 | 状态 |
|---|---|---|
| 应用工厂、封装、错误码、JWT、角色守卫 | `server/app/main.py`、`envelope.py`、`security.py`、`deps.py` | 42 条路由已挂载 |
| 采集入库、质量打分、去重、时钟容差 | `routers/capture.py` | 完成 |
| 复核、难例池 | `routers/review.py`、`routers/hard_samples.py` | 完成 |
| 数据集、报告、参数 | `routers/datasets.py`、`reports.py`、`system.py` | 完成 |
| 十三张表 | `server/app/models.py` | 完成；后四张的原因见 ADR 08 |
| 契约覆盖测试 | `tests/test_api_skeleton.py` | 通过——**不许削弱** |

**卡着 `P1-02` 的就是两条路由**，而且正是需要权重的那两条：

| 路由 | 需求 | 何时关闭 |
|---|---|---|
| `POST /api/detect/frames/{id}` | FR-M3-01 | `P2-05b` |
| `POST /api/detect/batches` | FR-M3-02 | `P2-05b` |

`POST /api/compare/frames/{id}` 原本也在这一列，**已移到 `P4-10`**：它需要同时加载两个已注册版本，
留在这里会让 `P1-02` 直到 P4 都关不掉。**这是对任务的更正，不是放宽。**

还缺什么：

1. **真实的检测链路。** `POST /api/detect/frames/{id}` 与 `/api/detect/batches` 因为没有权重返回
   501。启动时从 `model_version.weight_path` 加载一次模型，跑推理，写 `detect_object`，然后删掉
   这个 501。
2. **队列消费者。** `detect_task` 的行在写，没人消费。需要一个 worker：取排队任务、逐帧更新
   `progress`、取消在五秒内生效（AC-11）、失败带原因。
3. **`POST /api/detect/frames` 必须拒绝非采集来源的帧**（AC-10）——守卫写在处理函数里，不能只靠
   界面拦。
4. **统计跟随真实结果。** `/api/stats/*` 已按复核状态过滤；有真实检测数据后，核对数字与看板一致。

| 主张 | 检查方式 |
|---|---|
| 检测是真推理，不是假数据 | 跑一帧完整链路；框与「同一权重、同一图片」手工跑的结果一致；行里带着产出它的模型版本 |
| 队列真的在跑 | 提交 100 帧；进度单调递增；任务到 `done`；`obj_count` 与行数一致 |
| 取消真的生效 | 第 40 帧取消；五秒后不再出现新结果；任务状态为 `cancelled` |
| 失败的帧能重试 | 制造一次失败；任务为 `failed` 并带原因；重试后能跑完 |
| 没有回退 | `pytest` 不低于当前数量；**没有测试被跳过、没有断言被删** |

**前端抛给这条线的三个问题，做 socket 之前先答。** 采集页的客户端已经在说 `/ws/capture`，而它对照的
契约 §7 是不完整的：

1. **二进制帧里没有 `frame_id`**，§8 说的「按帧号对应结果」没有东西可对。要么帧消息带头部，要么约定
   「每帧之后的第一条 `detect` 即为该帧的结果」。
2. **`detect` 里没有质量分**，质量分环没有东西可显示。
3. **socket 的鉴权方式没写。** 客户端只能把 token 放进查询串，而 token 出现在 URL 里会漏进日志和
   referrer。定下来并写进 §7——常规做法是首条消息鉴权。

**三条都要在路由存在之前写进契约，不是之后。** 页面和服务端必须对同一个协议达成一致，而任何一方都
无法单独验证它。

### 2.2 数据集与第一次基线（任务 `P2-06`）

`models.py` 和 `train_experiment` 都在，但一次训练都没跑过。这条是**探索性**的一跑：把链路走通，
并让看板有真实数字。正式的 E0–E4 仍然留在 `P4-01..03`，在冻结数据集上做——**在 PR 里写清楚
这个区别**，别让人以为同一件事做两遍。

- **DUO 只划分一次，且确定。** 7782 张，官方测试集 1111 张冻结，其余 6671 张按 **85:15** 分成训练与
  验证。这是 `docs/test-plan-en.md` §2 的要求：验证集 10–15%，测试集至少 500 张且只用于报告、不用于
  调参。同一个种子必须给出同一个划分，**各项数量加起来等于总数**——要算，不要估。
- **`7:2:1` 不是这个划分。** 它是数据集导出功能（FR-M4-04）的比例，是应用运行时从复核池里生成的。
  这条任务早先的措辞把它套到了训练划分上——**那是组长的错，不该由你来调和。**
- **`scripts/prepare_dataset.py` 要改。** 它现在硬编码 `VAL_RATIO = 0.15`、不接受 `--seed`、不写清单。
  这些都是这条任务的一部分，并且要给「确定性」这个主张加测试。它已有的分组哈希保留——测试计划要求
  丢掉与训练集几乎重复的测试图。
- **在 GPU 上训练，用独立环境。** 运行环境装的是 CPU 版 torch，不要动它，另建一个训练环境。四次实验
  加消融在 CPU 上跑不是任何人能承受的排期，而且纯 CPU 的结果也会让后面的速度指标无从比较。
- **一次基线跑进 `train_experiment`**，指标列全部填上：`map50`、`map50_95`、`recall_avg`、`fps`、
  `params_m`，再加快照名、种子、轮次与批大小。**留空的指标格算这条没过。**
- **权重能通过 `model_version` 加载。** 登记版本、上线、并证明 `POST /api/detect/frames` 用的就是
  它——这才关上 2.1 的第 1 条。
- **说清数字意味着什么。** 如果 mAP@0.5 离 0.75 的目标很远，在 PR 里说明并给出一个假设，而不是留
  一个低分让别人以后自己发现。

### 2.3 每条路由的契约测试（任务 `P2-07`）

现有骨架测试覆盖了封装、守卫和 501，但**没覆盖每条路由返回载荷的形状**——而那正是前端会崩的地方。

- **P0 的每条路由至少一个测试**：状态码、`code` 字段、以及文档里写明的字段是否存在且类型正确。
- **反向证明一次**：从序列化器里删掉一个字段，测试必须红。做一次，并在 PR 里说明。
- 测试仍然不需要数据库服务器——和现在一样用 SQLite。
- **不要测框架。** 测的是 `docs/api-contract-en.md` 里本项目承诺的东西。

## 三、给孙健恒：界面

顺序有讲究：3.1 和 3.2 是机械活，做完之后其余的才好推。

### 3.1 让 `api.js` 说真话（任务 `P2-10`）

契约从 18 条扩到 42 条，当初叫 provisional 的每一条都在里面了。注释还在说它们不在，现在这句话
对每个读者都是误导。

- 删掉所有 `// provisional` 标记。
- **加一个能证明它不再回来的测试**——读 `api.js`，断言这个词出现 0 次。
- **加另一侧的检查**：每个导出的函数都能在 `docs/api-contract-en.md` §6 找到对应路由。有五条契约
  路由暂时没有前端调用方（`auth/login`、`auth/me`、`tasks/{id}`、`detect/frames`、
  `compare/frames`）——**不要去编造调用**，它们列在那里是给后端的。

### 3.2 登录（任务 `P2-11`）

`POST /api/auth/login` 是能用的——锁定、JWT、审计行，全都有。而页面只是校验加跳转。

- 调接口；存下 token；请求带上 `Authorization: Bearer`。
- **被拒时显示服务端返回的那句话**：里面带着剩余尝试次数和锁定时间。
- 任何页面收到 401 都要把用户送回登录表单，而不是显示一张空表。

### 3.3 加载、空、失败三态（任务 `P2-12`）

模拟数据永远不会失败，所以这些页面**从来没渲染过一次失败**。真实数据会失败。

- 每个调接口的页面都要渲染三种状态：加载中、空、出错。
- **把服务停掉再刷新页面**——应该看到一句人话，而不是空白面板或一直转的圈。
- **响应慢不能长得像空。** 这两件事看起来一样，用户会以为数据丢了。

### 3.4 采集页接真实帧流（任务 `P2-08`）

`capture.html` 现在播的是模拟检测。`/ws/capture` 在契约 §7 里写好了。

- 框来自 socket；连不上时退到轮询。
- 模拟路径仍要能通过 `USE_MOCK` 打开——没有后端的机器上，原型必须还能给人看。
- 质量分环、帧条、延迟数字都取同一批消息里的值，**不要出现第二个数据源**。
- **契约 §7 已经定稿，`live.js` 现在有两处不符合它。** 一是 token 放在查询串里，而 §7 明确禁止
  这样做（会漏进访问日志和 referrer），必须改成连接后的第一条 `auth` 消息；二是 §7 新增了
  `auth_ok`、`4401`、`4408` 三种情况，客户端要处理。`P2-16` 要求给这条协议加一个测试，做法与
  `tests/test_api_js.py` 相同：客户端与契约不一致时，测试必须失败。

### 3.5 数据集导出页（任务 `P2-09`）

路由已经在了：`GET`/`POST /api/datasets`，有真实划分和清单文件。

- 导出一个快照、列出来、刷新——这一页不留任何模拟数据。
- **页面上显示的划分数量必须等于服务端返回的**；这里对不上，导出就不可信。

### 3.6 需求跟踪矩阵（任务 `P2-14`）

课程要求根据需求定义书和 UI 原型做一份跟踪矩阵，**覆盖原型里的每一个界面**。模板是一份五个工作表的
Excel：封面、变更履历、矩阵本体，以及每个界面一张标注截图。

**矩阵是「一行一个 UI 元素」，不是一行一个界面。** 每行包括：编号、大分类（界面）、中分类
（header / form / actions / content）、小分类（控件）、详细说明，以及三列评审状态（PD / COD / UT）、
担当者与责任者。

详细说明用「参照图 N，图标 M」指到截图上。**这个引用就是整件事的意义**——评审能在图上直接找到那个
元素，而不是相信文字描述。

交付到仓库里用 Markdown，因为表格放进 PR 才有人看：

- `docs/traceability-en.md` 与 `docs/traceability-zh.md` 成对；英文为准，中文为对照。
- 截图放在 `docs/images/traceability/`，一页一张，按页面编号命名——`p02-home.png` 这样。
  标注可以直接画在图上；不方便画时，同一页的行按阅读顺序排列，并在页首说明「编号即行序」。
- 模板里的封面字段和变更履历，用简短的小节保留。
- 状态图例（完成 / 进行中 / 未着手）要**如实标**。用模拟数据的原型页，在评审眼里不算完成。

怎么算过关：

| 主张 | 检查方式 |
|---|---|
| 每个原型界面都覆盖到 | `web/templates/` 里的每个文件都在矩阵里作为「大分类」出现 |
| 图片是真的 | `docs/images/traceability/` 下引用的每个路径都存在于仓库 |
| 需求编号是真的 | 引用到的每个 `FR-Mx-xx` 都能在 `docs/srs-en.md` 表 3-1 找到 |
| 读者能跟着走 | 没看过这个应用的人，能照着截图找到三个指定元素 |

### 3.7 设计走查（任务 `P2-18`）

SRS 要求「深海蓝与青绿的海洋基调，不得使用医疗类蓝白风格」（§5.1）。`docs/copy-review-zh.md` 里九条文案
意见一直在等这样一次走查。两件事合成一条任务，因为它们本就是同一件事：**让十三个页面看起来像一台仪器，
而不是十三个页面。**

已经就位、要用而不是重做的：

| 部件 | 位置 |
|---|---|
| 颜色、字号、间距、布局尺寸 | `web/static/css/tokens.css`——唯一定义处 |
| 公共外壳：顶栏、菜单、页脚 | `web/static/js/layout.js`、`web/templates/*.html` |
| 页面级样式 | `web/static/css/app.css`，读 tokens |

- **关掉文案审阅**：侧边栏分组名、统计页副标题、看板 KPI 前缀。采纳或明确否决并写明理由；**静默留着的
  意见，正是这份文档要破的习惯**。
- **去掉十二个页头的 `P-xx` 角标**。它一直留着，是因为曾是「屏幕 ↔ SRS §5.2」唯一的锚；而这个锚现在由
  `docs/traceability-zh.md` 正式承担。
- **加一个测试，形状照 `tests/test_api_js.py`**：模板或 `app.css` 里出现十六进制颜色就让构建失败。
  **tokens 是唯一来源，而不被检查的规则一定会漂。**
- **每页一张截图**，放进 `docs/images/ui/`，让下一次设计争论是比较，而不是记忆。
- **不许回退**：页面测试、三态、以及今天已有的每个控件都要保留。

## 四、每条交接都要过的关

1. **仓库自己的检查在本地跑过，输出贴进 PR。** 全部，不是摘要：`ruff check`、
   `ruff format --check`、五份文档检查、`pytest`，动过固件还要 `pio run`。
2. **能当场演示。** 评审照着上表就能复现那条主张，不需要问作者怎么做。
3. **文档跟着代码走。** 路由变了就改契约；表结构变了就改数据模型和 `EXPECTED_COLUMNS`；
   只要会让读者相信一件假的事，就在同一个 PR 里改掉。
4. **偏离文档的决定要写 ADR。** 四个人的仓库，最付不起的失败就是「悄悄地不一致」。
5. **不许删测试、跳过测试来换绿。** 测试错了，指明哪一条、为什么。
6. **PR 里写清没做什么。** 「能跑」不是报告；写在描述里的已知缺口，比在答辩现场被发现的缺口值钱。

## 五、怎么关闭一条交接

事项验收通过后，删掉对应小节，在 `PLAN.md` 里勾掉任务，并在 `PROGRESS.md` 里记下日期与结果。
**一份列着已完成工作的交接文档会没人再读**，然后下一个人就会正好错过那条还重要的。
