## 一、这份文档怎么用

- 每人一节。每条说明**已经有什么**、**还缺什么**、**怎么验**。
- 验收标准要陌生人照着能跑、能判。「做得不错」不是标准。
- 这里没写的不在范围内。顺手做的改动欢迎，但单开 PR 说明理由，不要混进这些条目里。
- 第四节对这里每一条都成立——包括写给别人的那些。

### 还缺什么

1. **真实的检测链路。** `POST /api/detect/frames/{id}` 与 `/api/detect/batches` 现在返回 501，
   因为没有权重文件。启动时从 `model_version.weight_path` 加载一次模型，跑推理，写
   `detect_object`，让这个 501 消失。
2. **队列消费者。** `detect_task` 的行在写，没人消费。需要一个 worker：取排队任务、逐帧更新
   `progress`、取消在五秒内生效（AC-11）、失败要带原因。
3. **统计跟随复核口径。** `/api/stats/*` 已按状态过滤；有真实检测之后，核对数字与看板一致。
4. **`POST /api/detect/frames` 必须拒绝非采集来源的帧**（AC-10）——这条守卫写在处理函数里，
   不能只靠界面拦。

### 每条怎么验

| 主张 | 检查方式 |
|---|---|
| 检测是真推理，不是假数据 | 跑一帧完整链路；框与「同一权重、同一图片」手工跑的结果一致；`detect_object` 带着产出它的模型版本 |
| 队列真的在跑 | 提交 100 帧；进度单调递增；任务到 `done`；`obj_count` 与行数一致 |
| 取消真的生效 | 第 40 帧取消；五秒后不再出现新结果；任务状态为 `cancelled` |
| 失败的帧能重试 | 制造一次失败；任务为 `failed` 并带原因；重试后能跑完 |
| 没有假数据 | 剩下的 501 必须在消息里说清缺什么 |
| 没有回退 | `pytest -q` 不低于 114 通过；没有测试被跳过、没有断言被删 |

### 约束

- **不要改视觉模块**（`server/app/vision/`）——那是 A 线的，摄像头验收依赖它现在的行为。
- **不要改名或删列**：`EXPECTED_COLUMNS` 会让测试红，而且数据模型文档必须在同一个 PR 里改。
  真要改，先写 ADR。
- **不要加不加锁的依赖**：加依赖要固定版本，并在同一个提交里更新 CI 的依赖行。CI 只装一张
  很短的显式清单，别的不装。
- **不要为了让门禁变绿而关掉测试。** 测试写错了，在评审里说清为什么。

## 三、给孙健恒：界面技术债

三条，按顺序做。前两条是机械活，一个 PR 能清完。

### 3.1 `provisional` 注释已经全部失效

契约从 18 条扩到 42 条（`docs/api-contract-en.md` §6），当初叫 provisional 的 24 条**都在里面**。
`web/static/js/api.js` 里的注释还在说它们不在，现在这句话对每个读者都是误导。

- 删掉所有 `// provisional` 标记——那些路由一条都不是 provisional 了。
- 加一个防止它回来的检查：读取 `api.js`、断言这个词出现 **0 次**的测试，将来的改动没法悄悄
  把混乱加回来。
- 再加一侧的检查：**`api.js` 里的每个函数都能在契约里找到对应路由**。契约里有五个前端暂未调用的
  路由——`auth/login`、`auth/me`、`tasks/{id}`、`detect/frames`、`compare/frames`——不要去编造
  调用方，它们列在 §6 里是给后端的，等页面真的需要再接。

### 3.2 登录页没有调后端

`web/templates/login.html` 校验通过就跳 `home.html`。`POST /api/auth/login` 是能用的——锁定、
JWT、审计行，全都在。

- 接口可达时调它；只有模拟数据时可保留跳转。
- **登录被拒要显示服务端返回的那句话**，不要用笼统提示：服务端已经给出了剩余次数和锁定时间。

### 3.3 文案建议

`docs/copy-review-zh.md` 里有九条，其中三条标为优先：侧栏分组名、统计页四个副标题、工作台
指标的「今日」前缀。**按组长批准的那几条做**；文档里已经记过哪些改过了，别做第二遍。

## 四、每条交接都要过的关

1. **仓库自己的检查在本地跑过，输出贴进 PR。** 七项全贴，不要只写「已通过」。
2. **能当场演示。** 评审照着上表就能复现那条主张，不需要问作者怎么做。
3. **文档跟着代码走。** 路由变了就改契约；表结构变了就改数据模型和 `EXPECTED_COLUMNS`；
   只要会让读者相信一件假的事，就在同一个 PR 里改掉。
4. **偏离文档的决定要写 ADR。** 四个人的仓库，最付不起的失败就是「悄悄地不一致」。
5. **不许删测试、跳过测试来换绿。** 测试错了，指明哪一条、为什么。
6. **PR 里写清没做什么。** 「能跑」不是报告；写在描述里的已知缺口，比在答辩现场被发现的缺口值钱。

## 五、怎么关闭一条交接

事项验收通过后，删掉对应小节，并在 `PROGRESS.md` 里记下日期与结果。**一份列着已完成工作的交接
文档会没人再读**，然后下一个人就会正好错过那条还重要的。
