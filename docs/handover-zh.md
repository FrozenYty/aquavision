## 一、这份文档怎么用

- 每人一节。每条说明**已经有什么**、**还缺什么**、**怎么验**。
- 验收标准要陌生人照着能跑、能判。「做得不错」不是标准。
- 任务编号与 `PLAN.md` 一致；两者冲突时以 `PLAN.md` 为准，并修正本文档。
- 第四节对这里每一条都成立——包括写给别人的那些。

| 主张 | 检查方式 |
|---|---|
| 检测是真推理，不是假数据 | 跑一帧完整链路；框与「同一权重、同一图片」手工跑的结果一致；行里带着产出它的模型版本 |
| 队列真的在跑 | 提交 100 帧；进度单调递增；任务到 `done`；`obj_count` 与行数一致 |
| 取消真的生效 | 第 40 帧取消；五秒后不再出现新结果；任务状态为 `cancelled` |
| 失败的帧能重试 | 制造一次失败；任务为 `failed` 并带原因；重试后能跑完 |
| 没有回退 | `pytest` 不低于当前数量；**没有测试被跳过、没有断言被删** |

**契约 §7 已经定稿，两侧都已实现。** socket 用首条 `auth` 消息鉴权并回 `auth_ok`；token 无效以

## 三、给孙健恒：界面

这一节的内容都已交付并有测试；本线剩下的任务是 `P3-02`（统计看板）、`P3-07`（报告生成与历史）与
`P3-15`（物种阈值页，与后端线共担）。

### 3.1 让 `api.js` 说真话（任务 `P2-10`）

客户端对契约是诚实的：`api.js` 里没有任何 `provisional` 标记，每个导出函数都能在
`docs/api-contract-en.md` §6 找到对应路由，任何一条不再成立时 `tests/test_api_js.py` 都会失败。
仍有四条契约路由没有前端调用方（`auth/me`、`tasks/{id}`、`detect/frames`、`compare/frames`）——
它们列在那里是给后端的，不要去编造调用。

### 3.2 登录（任务 `P2-11`）

登录已接真实接口：页面调用 `POST /api/auth/login`，存下 token 并以 `Authorization: Bearer` 发送；
被拒时显示服务端返回的那句话（带剩余尝试次数与锁定时间）；任何页面收到 401 都会把用户送回登录表单。
锁定、JWT 与审计行由 `tests/test_api_skeleton.py` 覆盖。

### 3.3 加载、空、失败三态（任务 `P2-12`）

每个调接口的页面都通过 `web/static/js/ui.js` 里的 `loadInto` 渲染三种状态：加载中、空状态提示、
带重试的出错提示。响应慢时会说明慢，而不是看起来像空。新写的调用也走这个辅助函数，这样以后新加的
页面不会悄悄地只渲染成功态。

### 3.4 采集页接真实帧流（任务 `P2-08`）

`capture.html` 走 `/ws/capture` 实时流，这个协议由 api-contract 第七节定义、由
`server/app/routers/live.py` 提供；轮询只是 socket 无法提供时的兜底。质量分环、帧条、延迟数字都取
同一批消息里的值，不出现第二个数据源；模拟路径仍可通过 `USE_MOCK` 打开。

**契约 §7 与客户端一致。** token 走首条 `auth` 消息，不进 URL；`auth_ok`、`4401`、`4408` 都已处理；
二进制 JPEG 紧跟对应的 `frame` 消息；结果带 `frame_id` 与质量分。`tests/test_live_socket.py` 约束
客户端，`tests/test_ws_capture.py` 约束服务端。**已知限制、挂在 `P3-12`：** `auth_ok` 之后 socket
才断开的情况只会报「已关闭」，不会退回 REST 轮询。

### 3.5 数据集导出页（任务 `P2-09`）

这一页已接真实接口：`GET`/`POST /api/datasets` 支撑快照表单与历史，页面显示的划分数量来自服务端
返回，整页不再有模拟数据。划分数量与返回不一致，仍然是让导出不可信的那个缺陷。

### 3.6 需求跟踪矩阵（任务 `P2-14`）

`docs/traceability-en.md` 与 `docs/traceability-zh.md` 就是这份矩阵：一行一个 UI 元素，带封面、
变更履历、PD/COD/UT 状态，以及 `docs/images/traceability/` 下每个界面一张标注截图。它以 SRS 为准：
大分类名称跟随 SRS §5.2，引用到的每个 `FR-Mx-xx` 都能在表 3-1 找到。界面或元素变化时更新矩阵，
并重截对应截图。

它按这些标准核对：

| 主张 | 检查方式 |
|---|---|
| 每个原型界面都覆盖到 | `web/templates/` 里的每个文件都在矩阵里作为「大分类」出现 |
| 图片是真的 | `docs/images/traceability/` 下引用的每个路径都存在于仓库 |
| 需求编号是真的 | 引用到的每个 `FR-Mx-xx` 都能在 `docs/srs-en.md` 表 3-1 找到 |
| 读者能跟着走 | 没看过这个应用的人，能照着截图找到三个指定元素 |

### 3.7 一个页面只有一个名字（任务 `P2-18`）

SRS §5.2 的名字是唯一一套——对象加动作，能四字就四字，不带「页」后缀，不用连词——菜单、两个页标题、
SRS 与矩阵都使用它：

| | | | |
|---|---|---|---|
| 登录 | 运行总览 | 采集控制 | 影像浏览 |
| 识别任务 | 结果详情 | 人工复核 | 难例样本 |
| 数据导出 | 统计分析 | 巡检报告 | 模型实验 |
| 系统设置 | | | |

`tests/test_page_names.py` 让四份清单保持一致，任何一份漂移、或两个模板名只差一个字符，测试都会失败。
**不要改功能名：** `FR-M4-01` 在 SRS 里仍是「复核工作台」；页面名、需求名、路由名与表名是四件事。

## 四、每条交接都要过的关

1. **仓库自己的检查在本地跑过，输出贴进 PR。** 全部，不是摘要：`ruff check`、
   `ruff format --check`、文档检查、`pytest`，动过固件还要 `pio run`。
2. **能当场演示。** 评审照着上表就能复现那条主张，不需要问作者怎么做。
3. **文档跟着代码走。** 路由变了就改契约；表结构变了就改数据模型和 `EXPECTED_COLUMNS`；
   只要会让读者相信一件假的事，就在同一个 PR 里改掉。
4. **偏离文档的决定要写 ADR。** 四个人的仓库，最付不起的失败就是「悄悄地不一致」。
5. **不许删测试、跳过测试来换绿。** 测试错了，指明哪一条、为什么。
6. **PR 里写清没做什么。** 「能跑」不是报告；写在描述里的已知缺口，比在答辩现场被发现的缺口值钱。

## 五、怎么关闭一条交接

事项验收通过后，删掉对应小节，在 `PLAN.md` 里勾掉任务，并在 `PROGRESS.md` 里记下日期与结果。
**一份列着已完成工作的交接文档会没人再读**，然后下一个人就会正好错过那条还重要的。
