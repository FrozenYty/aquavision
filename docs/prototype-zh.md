# 系统原型方案

> 本文为 `prototype-en.md` 的中文对照版，以英文版为准。
> 维护人：@chemflowers · 重审时机：原型被 P2 的正式切片取代时
> 有效期：到走查被正式链路替代为止，之后本文只是历史。

目标：让人在 3 分钟内**点着走一遍主线**，相信这是一个能用的系统。不是功能完整，是**形状可信**。

## 一、范围：6 屏，一条线

| # | 屏 | 现状 | 本轮工作 |
|---|---|---|---|
| 1 | 登录 | 已有 | 保持，只微调 |
| 2 | 总览 | home 已有，内容薄 | **改造**：4 个指标卡 + 1 张趋势图 |
| 3 | 采集与实时识别 | capture 已有，无框 | **改造**：画面叠框 + 质量分仪表 + 帧列表 |
| 4 | 帧详情 | 无 | **新增**：大图 + 框 + 目标列表 + 去复核 |
| 5 | 复核工作台 | 无 | **新增**：画布拖框 + 改类别 |
| 6 | 统计与报告 | 无 | **新增**：4 张图 + 导出按钮 |

其余 7 屏不做，侧栏里灰掉并标 `P2`——读起来是排期，不是没做完。

## 二、演示动线

```
登录 → 总览（今日 412 帧 / 待复核 7）→ 点「开始采集」
     → 画面出框、质量分 86、延迟 128 ms
     → 点一帧进详情 → 发现一个错框（礁石被判成海参）
     → 去复核 → 拖一个框、改类别 → 计数 10 → 11
     → 回统计 → 生成报告 → 点导出
```

**每一个箭头都必须能点。** 走不通的地方，评委会当成没做完。

## 三、每屏的关键元素

**总览**——四张卡（今日采集、待复核、质量拦截率、在线模型），数字 ≥ 28 px，下面一张七日折线，
底部一行最近的会话。

**采集**——这一屏决定成败。实时画面叠框，框上标类别与置信度；四类固定色（海参橙、海胆紫、扇贝粉、
海星黄）；角落一个延迟数字，每两秒跳一次；质量分用环形或大数字，低于 60 变黄并显示「需重拍」；
底部一条最近帧的缩略图带。

**帧详情**——大图带框，右侧目标列表（置信度与状态），一个按钮通向复核。

**复核**——最能加分的一屏。画布加可拖拽的框，选中框显示四角手柄；右侧目标列表可确认、修改、删除、
新增；工具栏为选择、画框、删除、撤销，加缩放比例、改类别下拉与提交按钮。
**做到拖一个框、改一次类别就成立**，不必真的缩放，不必撤销栈。

**统计**——四张图 2×2：物种组成、采集量、拦截率、修正分布。右上两个按钮：生成报告、导出 PDF。
弹个轻提示即可，不用真生成文件。

## 四、采集端怎么呈现

| 方案 | 画面来源 | 真实度 | 成本 |
|---|---|---|---|
| **A 浏览器开笔记本摄像头** | `getUserMedia()` | 画面真、框假 | 二十行 |
| **B 数据集真实水下图** | DUO 样张 | 数据真、实时假 | 零 |
| C 纯占位 | 灰框 | 全假但声明清楚 | 零 |

**默认用 B**：从 7782 张 DUO 影像里挑 3–5 张，框手工摆位，**依次淡入**——比全部同时出现更像在检测。

**顺手做 A**：采集页放一个「试一下本机摄像头」按钮。评委问「图从哪来」时当场点开。此模式下**不叠框**，
笔记本对着桌面，叠框反而假。

三处标注必须到位：页头角标 `原型演示 · 模拟数据`；采集页脚注 `影像来自 DUO 公开数据集样张；
正式版由 USB 摄像头实时供帧`；统计页脚注 `数字为演示数据，非真实运行结果`。

**评委能接受模拟数据，不能接受被骗。**

## 五、Mock 数据

统一放 `web/static/mock/fixtures.js`，形状沿用 `api-contract`：

```js
{ frame_id: "20261105T193012-0042", session_id: "s-a3-007",
  captured_at: "2026-11-05T19:30:12+08:00",
  quality: { sharpness: 78, brightness: 91, colorcast: 85, score: 86, verdict: "ok" },
  width: 1920, height: 1080 }

{ class_code: "holothurian", confidence: 0.87, x: 0.41, y: 0.52, w: 0.12, h: 0.09 }
```

**框要手工摆**，八到十二个，落在真实目标位置上。随机生成的框会飘在空白水面，一眼假。
