# 界面文案审阅

> 本文为 `copy-review-en.md` 的中文对照版，以英文版为准。
> 维护人：@FrozenYty · 重审时机：界面文案重写时，或页面集合变化时

对十三个页面文案的审阅结论与修改建议。**这是一份审阅，不是变更记录**：除第六节注明者外，
下面的改动**都还没有做**。

## 一、范围与方法

把所有用户能看到的字符串从模板和生成它们的脚本里抽出来，查了两遍：

1. **机械层面** —— 重复字、中文句内的半角标点、中英之间缺空格、多余感叹号。
2. **判断层面** —— 同级标签是否对仗、一列文字是否有节奏、用词是否符合词汇表、有没有开发用语。

结论主要来自第二遍；第一遍什么都没查出来。

## 三、版式与对仗

**侧栏分组名。** 三个组是两字，三个组是五字：

```
概览(2) · 采集(2) · 识别(2) · 复核与回流(5) · 统计与报告(5) · 模型与系统(5)
```

侧栏是一列竖排文字，长度不齐会让右边缘每一页都参差。建议：概览 · 采集 · 识别 · 复核 · 统计 ·
模型——六组各两字，省掉的字（回流、报告、系统）由下面的子项承担。

**统计页四张卡的副标题。** 四张图量的东西不同，副标题却没有统一地说明：

| 卡片 | 副标题 | 字数 |
|---|---|---|
| 物种组成 | 近 7 日目标框数 | 7 |
| 采集量趋势 | 每日收帧 | 4 |
| 质量拦截率 | 低质量帧占比 | 6 |
| 复核修正分布 | 人工改动汇总 | 6 |

三个问题叠在一起：字数 4/6/7 不齐；结构不同（一个给时间范围、一个给频率、两个给定义）；
「收帧」是内部简称，另外三处都是普通词。

建议：目标框数 · 采集帧数 · 重拍帧占比 · 改动次数。前两个顺带澄清一个真实歧义——**一个数框、
一个数帧，现在读者分不出来**。

**工作台指标标签。** 今日采集(4) · 待复核(3) · 质量拦截率(5) · 在线模型(4)。前三个是「今天的数」，
第四个是「当前状态」，标签上没做区分。还有一个准确性问题：**质量拦截率没写「今日」，但数字是当天的**。

建议：今日采集 · 今日待复核 · 今日拦截率 · 当前模型——前三个共用一个前缀，第四个自己声明不同，
语义分组和视觉分组就一致了。

## 四、单位、状态词与表单标签

**界面上唯一的拉丁单位。** `识别间隔（ms）` 是全站唯一用拉丁字母写的单位，其余都是中文（帧、秒、
像素、%）。建议改为 `识别间隔（毫秒）`。

**状态词本来有体例**——「待 X」表示等待，「已 X」表示已定：

```
待复核 / 已确认 / 已修改 / 已驳回
排队中 / 运行中 / 已完成 / 已失败
```

难例池的来源标签用了被动式，打破了它：低置信 / **被修正** / 跨模型不一致。第二个应为「已修正」。
三个标签在同一行里跑 3/4/6 个字，三个按钮宽度差别很大；改成「低置信 / 已修正 / 模型分歧」可以拉平，
代价是丢掉「跨模型」四个字。**这个交换值得说明，不值得隐瞒。**

**有一个标签少了一个词。** 参数列表里「默认置信度阈值」挨着「质量分阈值」——两个都是默认值，只有
一个写了「默认」。建议补成「默认质量分阈值」。

**句末标点。** 长提示基本都带句号，唯一一个完整的句子却没带：`超出范围的项会标红并拒绝保存`。
建议立一条规则：完整句加句号，短语不加。

## 五、不建议改的

对仗不值得拿语义去换：

| 项 | 保留理由 |
|---|---|
| 页面标题「工作台」「难例池」（3 字） | 这三个名字出自 SRS §5.2，改了就和规格对不上 |
| 表头「创建时间」「登记时间」（4 字） | 表格里四个字是常态，缩短会丢信息 |
| `mAP@0.5` 与「平均召回」并列 | 指标名保留英文形态，翻成中文只会更难认，不是更好认 |
| 五个参数标签长度不等 | 表单标签是竖排在各自输入框上方的，右边缘本来就不对齐。强行等长会删掉「中间文件」「批量识别」，而这两个词说明了参数作用范围 |

**还有一条更早的建议被撤回**：把「检测框」改成「目标框」。词汇表早已把「检测框」定为唯一叫法，
审阅意见如果和词汇表冲突，正好会制造词汇表本来要防的那种漂移。
